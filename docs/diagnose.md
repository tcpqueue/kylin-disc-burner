## 光盘诊断

点主界面刻录机右边的“**光盘诊断…**”。

![光盘诊断](images/discburner_diag.png)

窗口最上面是**结论和建议**（✔ 正常 / ▲ 需要注意 / ✖ 有问题，其余为说明），下面是详细信息：

| 项目 | 说明 |
|---|---|
| 光驱 | 厂商、型号、固件版本 |
| 光盘类型 / 盘片制造商 | 如 `DVD+R`，以及盘片上记录的制造商代码 |
| 盘片状态 | 空白盘 / 可追加 / 已封盘 / **会话未关闭** |
| 会话 / 轨道 | 每个会话的类型（ISO9660 或其他格式，例如 UDF）、起始扇区、大小、卷标 |
| 已用 / 剩余 | 光盘容量 |
| 文件系统 | 如 `ISO9660 + Joliet`、`UDF 2.01`、`UDF 1.02 桥接`，或“未识别” |
| 系统可读容量 | 内核看到的容量；会话没关好的盘这里常常是 0 |
| 内核 UDF 支持 | 已启用 / 有模块 / 没有 |
| 挂载状态 | 是否已挂载、挂载点 |
| 只剩短名的文件 | 文件名已经变成 `2023__~1.XLS` 这类短名的文件数量 |

下面的按钮会按光盘情况出现：

| 按钮 | 何时出现 |
|---|---|
| 挂载并打开 / 打开 / 卸载 | 光盘有可识别的文件系统时 |
| 修复未关闭会话 | 检测到未关闭的会话时 |
| 恢复长文件名 | 发现只剩短名的文件，并且能从早先的会话找回原名时 |
| 复制诊断报告 | 总是有。完整报告（含 xorriso、blkid 原始输出）复制到剪贴板 |

每次诊断的报告还会自动保存到 `~/.local/share/discburner/logs/diag-*.txt`，内网机器可以拷出来分析。

诊断以**共享只读**方式访问光驱，不会写入任何数据；光盘已经被系统自动挂载时也不用先卸载。

## 挂载 UDF 光盘

Windows 用“类似于 USB 闪存驱动器”方式刻的光盘是 **UDF** 格式。麒麟内核支持读取 UDF 2.50 及以下版本，但有时文件管理器没有自动挂载，或者中文名显示不对。

在诊断窗口点“**挂载并打开**”：

- 通过 udisks 挂载，和文件管理器自动挂载的方式一样，普通用户即可操作；
- 自动使用 UTF-8，中文文件名正常显示；
- 挂载后直接打开文件管理器。

挂载失败时，程序会给出可以在终端执行的手动挂载命令，例如：

```bash
sudo mkdir -p /mnt/cd && sudo mount -o ro,iocharset=utf8 /dev/sr0 /mnt/cd
```

> [!NOTE]
> UDF 光盘只能读取，本软件不会往 UDF 光盘里追加。如果想用本软件继续刻录，请把文件拷出来，再刻到新盘上。

## 恢复长文件名

![恢复长文件名](images/discburner_recover.png)

### 这种盘是怎么来的

1. 麒麟自带刻录软件刻了一个**没有 Joliet** 的会话，盘上只有 Rock Ridge 长文件名和 ISO9660 短名；
2. 后来有人在 Windows 上往同一张盘追加文件。Windows 不认 Rock Ridge，只能看到 `2023__~1.XLS` 这样的短名，于是把短名写进了自己新建的 Joliet 目录；
3. 从此以后，无论在 Windows 还是麒麟上，这些文件都只显示短名。

### 为什么能找回

多会话光盘上，文件的**数据只写一次**，各个会话的目录只是指向同一段数据。早先会话里**起始扇区和大小都完全相同**的文件，就是同一个文件，它还带着原来的中文名。

### 操作步骤

1. 光盘诊断发现只剩短名的文件时，会出现“**恢复长文件名…**”按钮；
2. 程序逐个读取早先的会话，按文件位置找回原名，列出“当前名字 → 恢复为 → 原名来自哪个会话”，可以逐项取消勾选；
3. 点“写入光盘”，追加一个**只改名字**的会话：文件内容不重写，只占几百 KB；
4. 写完自动读回核对。

找不到原名的文件保持原样。为了避免张冠李戴，以下情况会跳过：

- 大小为 0 的空文件（它们在光盘上可能共用同一个位置）；
- 同一个会话里有多个文件指向同一位置；
- 当前目录里有多个文件指向同一位置。

改名会话按主界面选的刻录速度写入，盘片写入后仍然可以追加。

普通刻录时，如果盘上还有只剩短名的文件，确认框里也会提醒先恢复。

## 修复未关闭的会话

### 什么情况下会出现

Windows 用“类似于 USB 闪存驱动器”方式刻录后，如果没有正常弹出（直接按光驱按钮、拔 USB 线、断电），最后一个会话可能没有关闭。这样的盘在麒麟和其他电脑上可能读不出来。

### 怎么修复

放入光盘后，主界面刷新时会自动检测，发现后弹窗询问是否修复。选“否”也可以稍后点右上角的“**修复未关闭会话…**”按钮。

![发现未关闭的会话](images/discburner_repair.png)

修复相当于执行：

```bash
xorriso -outdev /dev/sr0 -close off -close_damaged as_needed
```

- 只关闭那个会话，**不删除已有数据**，光盘仍然可以继续追加；
- `as_needed` 表示光驱没有报告未关闭的轨道时，什么都不写；
- 光驱没有标记“损坏”，但能看出轨道没写完的情况（见下文），改用 `-close_damaged force`；
- 支持 CD-R/RW、DVD±R（含双层）、DVD-RW、BD-R；
- 修复后弹出再放入，系统即可正常读取。

### 检测依据

| xorriso `-toc` 输出 | 含义 |
|---|---|
| `but next track is damaged` | 光驱报告有损坏 / 未关闭的轨道 |
| `Incomplete session encountered !` | CD 上有不完整的会话 |
| 已写扇区多于可读扇区，并且读不出目录 | 轨道写了一部分但没关闭，光驱并没有标记损坏 |

光盘目录读不出时，xorriso 的 `-indev` 方式连光驱都不会接管，本软件会改用 `-outdev` 只读取光驱状态，因此不会误报“没有光盘”。

### 能做到和做不到的

- **能**：让已经写好、只是没有关闭的数据重新可读。
- **不能**：恢复写到一半被打断的数据。如果 Windows 当时正在写入，最后那次写入的文件可能找不回来，之前写好的不受影响。
- **不能**：救回从来没有写入有效数据的盘。例如 Windows 格式化 UDF 时中途失败，盘上没有有效的文件系统，关闭轨道后也只是一张“正常关闭的空盘”。

> [!IMPORTANT]
> **刻录中途出错时，不要急着弹出或断电**，先用本软件诊断。实测发现，部分光驱在重新上电后会自动关闭没写完的轨道，盘就变成“已关闭、没有可读数据”，再也无法使用。

> [!WARNING]
> **验证状态**：检测逻辑基于真实光驱在这种状态下的输出编写和测试；“关闭未关闭会话”这一步**尚未在真实的未关闭光盘上验证**。如果你遇到这种盘，欢迎把诊断报告提交到 Issue。

## 诊断结论速查

| 诊断结论 | 意思 | 怎么办 |
|---|---|---|
| ✔ 标准数据盘（ISO9660 + Joliet） | 一切正常 | 可以直接追加 |
| ▲ 标准数据盘，但没有 Joliet 文件名 | 麒麟自带刻录刻的盘，Windows 上是短名 | 用本软件追加任意一个文件，Windows 上的名字就会恢复正常 |
| ▲ 有文件只剩短名 | 见[恢复长文件名](#恢复长文件名) | 点“恢复长文件名…” |
| UDF 格式的盘 | Windows“类似 U 盘”方式刻的 | 点“挂载并打开”读取；不能用本软件追加 |
| ✖ 内核没有 UDF 支持 | 系统读不了 UDF | 联系管理员加载 `udf` 内核模块 |
| ✖ 有会话没有关闭 | 见[修复未关闭的会话](#修复未关闭的会话) | 点“修复未关闭会话…” |
| ✖ 盘片已被关闭，但没有能读出的数据 | 这张盘已无法使用 | 换盘 |
| 已封盘 | 不能再写入 | 只能读取 |
