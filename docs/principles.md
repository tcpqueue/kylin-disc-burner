## 麒麟自带刻录的问题出在哪

银河麒麟 V10 SP1 自带的刻录软件 `kylin-burner` 由 K3b 改造而来，底层调用 xorriso。从程序中可以读出它使用的命令模板，其中两条是：

```bash
xorriso -dev %1 -map "%2" "%3" -volid "%4" -close off -commit -speed min -eject
xorriso -dev %1 -map "%2" "%3" -volid "%4" -close on  -commit -speed min -eject
```

问题有两个：

1. **没有 `-joliet on`**。xorriso 默认只写 ISO9660 + Rock Ridge。Linux 读 Rock Ridge，显示正常；Windows 不认 Rock Ridge，只能退回 ISO9660 的 8.3 短名，中文全部变成下划线。
2. **使用 `-close on`**。这会关闭整张光盘，以后不能再写入。

用麒麟自带的 xorriso 按同样参数复现，再在 Windows 上挂载镜像核对：

| 刻录方式 | Windows 中看到的名字 |
|---|---|
| 麒麟方式（无 Joliet） | `____.DOCX`、`2025__________.XLSX`、`____\________.DOC` |
| 本软件 | `工作报告.docx`、`2025年度预算表（最终版）.xlsx`、`项目资料\会议纪要 第三次.doc` |

## 光盘文件系统简介

| 文件系统 | 谁会读 | 文件名 |
|---|---|---|
| ISO9660 | 所有系统 | 8.3 大写短名，只允许 `A-Z 0-9 _`，中文变下划线 |
| Rock Ridge | Linux、macOS | 叠加在 ISO9660 上，长名、权限、符号链接 |
| Joliet | Windows、Linux、macOS | 另建一棵 UCS-2 目录树，支持中文。标准限制 64 字符，扩展到 103 字符 |
| UDF | 所有现代系统 | Windows“类似 U 盘”方式和蓝光使用，适合随机写 |

本软件在同一个会话里**同时写 ISO9660、Rock Ridge 和 Joliet**：Linux 读 Rock Ridge，Windows 读 Joliet，各取所需，两边看到的都是原名。

## 多会话与“封盘”

一次性光盘（CD-R、DVD±R、BD-R）不能改写已经写过的位置，只能往后接着写。每写一次就是一个**会话**（session）：

```text
┌──────────────┬──────────────┬──────────────┬─────────────────────┐
│  会话 1      │  会话 2      │  会话 3      │   空白，可继续追加  │
│  文件 A、B   │  文件 C      │  文件 D      │                     │
│  目录：A B   │  目录：A B C │  目录：A–D   │                     │
└──────────────┴──────────────┴──────────────┴─────────────────────┘
```

- 每个新会话的目录都包含**之前所有文件**，指向它们原来的位置，文件数据不重复写；
- Windows 只读最后一个会话的目录，因此能看到全部文件；
- 每个会话有一定的开销：DVD 约几 MB，CD 约 7～14 MB；
- **关闭会话**（`-close off`）：本次写完，以后还能追加；
- **封盘**（`-close on`）：关闭整张光盘，以后永远不能再写。

替换同名文件时，新会话的目录指向新数据，旧数据仍然留在盘上、占用空间，只是看不到了。

## 本软件的 xorriso 参数

| 参数 | 作用 |
|---|---|
| `-joliet on` | 写 Joliet 目录树，Windows 显示原名 |
| `-compliance joliet_long_names:joliet_long_paths` | Joliet 名字最长 103 字符，路径不限 240 字符 |
| `-rockridge on` | 写 Rock Ridge，Linux 显示原名和权限 |
| `-local_charset UTF-8` | 不受启动环境 locale 影响，中文名不会被转坏 |
| `-close off`（默认） | 只关闭会话，不封盘 |
| `-md5 on` + `-check_md5_r` | 记录每个文件的 MD5，刻完逐个读回比对 |
| `-file_size_limit off --` | 支持单个大于 4 GB 的文件（末尾的 `--` 是 1.5.2 必需的） |
| `-abort_on FAILURE` + `-return_with FAILURE 32` | 出错立即停止，并通过返回码报告 |

刻录前，程序会先卸载被系统自动挂载的光盘，否则光驱被占用无法写入。

另外，**已经被麒麟刻坏名字、但还没封盘的旧盘**也能修好：用本软件往里追加任意一个文件，新会话会给盘上全部新旧文件生成 Joliet 名，Windows 上旧文件的名字也会恢复正常。

## xorriso 1.5.2 的“;1”问题

ISO9660 和 Joliet 标准里，文件名后面可以带版本号，例如 `工作报告.docx;1`。Windows 刻盘（IMAPI2）会写上这个 `;1`，读取时再把它去掉。

xorriso **1.5.2**（麒麟 SP1 自带）加载 Windows 刻的盘时，会把 `;1` 当成文件名的一部分读进来。追加之后新目录里的名字就成了 `工作报告.docx;1`，Windows 把它显示为 `工作报告.docx_1`，扩展名变了，双击就打不开了。麒麟自带刻录软件同样调用 1.5.2，所以也会出这个问题。

xorriso **1.5.8** 会正确去掉版本号。因此本软件：

1. 默认使用安装包自带的 xorriso 1.5.8，系统有 1.5.8 或更新版本时才用系统的；
2. 自带的运行不了、只能退回系统 1.5.2 时，刻录前在同一个会话里用 `-move` 把带 `;1` 的名字改回原名，确认框里会写明修正了几个文件。

## 麒麟对 UDF 的支持

通过分析麒麟 V10 2020 版（内核 4.4）和 SP1 2503（内核 5.4）自带的 `udf.ko` 内核模块：

| | 最高可读 UDF 版本 | 最高可写 UDF 版本 |
|---|---|---|
| 麒麟 V10 2020 版 | 2.50 | 2.01 |
| 麒麟 V10 SP1 2503 | 2.50 | 2.01 |

- Windows 默认的 UDF 2.01 和 2.50 都可以读取；
- 蓝光常用的 UDF 2.60 内核会拒绝挂载；
- 内核驱动“可写”指可覆盖介质（如格式化过的 DVD-RAM），对一次性光盘没有意义。

本软件**不往 UDF 光盘里追加**：UDF 和 ISO9660 的多会话结构不同，追加 ISO9660 会话会让 Windows 看不到原来的 UDF 内容。

## 为什么这样打包

目标是让内网机器 `dpkg -i` 一次就装好，不需要任何依赖：

| 决定 | 原因 |
|---|---|
| 在 Ubuntu 16.04（glibc 2.23）里编译 | 麒麟 2020 版基于 16.04，按最老的 glibc 编译，新系统也能运行 |
| 自带 xorriso 1.5.8 | 2020 版没有 xorriso；SP1 的 1.5.2 有“;1”问题 |
| 自带 Python 3.5 + PyQt5 5.5（PyInstaller 3.6） | 系统没有 PyQt5 时也能运行；PyInstaller 3.6 是支持 Python 3.5 的最后一版 |
| 优先用系统 Python/PyQt5 | 界面跟随系统主题，输入法插件与系统版本一致 |
| 不打包 X11 / GL / 字体相关的库 | 桌面系统一定有，打包旧版本反而会和新显卡驱动冲突 |
| 用 xz 压缩 deb | 新版 dpkg 默认的 zstd 在麒麟的 dpkg 1.18 / 1.19 上解不开 |
| 不声明 `Depends` | 所有依赖都在包里，避免内网机器因为缺包装不上 |
| 代码兼容 Python 3.5、Qt 5.5 | 麒麟 2020 版系统自带 Python 3.5.2、Qt 5.6.1 |
